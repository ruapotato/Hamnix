# CI status triage — 2026-07-25 (Hamnix CI has been RED for days)

Base SHA of this investigation: `438fca0a`.

## TL;DR

CI was red because **Tier 1 → "Optimizer battery (test_opt_\*)"** failed, and
because that step fails early **every later Tier-1 step was skipped** — the
whole browser / hamUI / DE-menu block never ran. CI therefore provided almost
no signal.

**44 of 52 `scripts/test_opt_*.sh` failed. None of them was a correctness
regression in a shipped path.** 43 fail because they assert that an optimizer
lane that was **deliberately retired** still fires; 1 (`test_opt_reglower`)
additionally uncovered a **real, still-open bug** in the replacement SSA
pipeline.

## Root cause: the opt1 lane was retired, the guards were not

Commit `ba2e4bcf` (2026-07-21) — *"feat(compiler): retire legacy opt1 — SSA
pipeline is the only optimizer"* — deleted `adder/compiler/opt.ad` and rewired
`--opt`:

* `--opt` now arms the **SSA pipeline** (`ssa_enable()`), i.e. it is exactly
  equivalent to `ADDER_OPT2=1`
  (`adder/compiler/fused_driver_host_main.ad:1243-1252`, `:1365-1400`).
* The host dump driver (`tests/fuzz/ad_codegen_dump_driver.ad`) no longer calls
  `ra_enable()` on the **codegen** path — the only remaining call site is the
  `--dump-regalloc` *analysis* lane (`:905`). So `ra_enabled == 0` during
  emission and **every codegen lever gated on it is structurally inert**:
  BASEHOIST, IDXREG, ISEL, DESTSEL, ACCSEL, IDXSTORE, ALELIDE, PARAMHOME,
  SPLITHOIST, STOREELIM, SPINELEAF, VEC, IVSR, STRENGTHRED, …
* The opt1 AST-pass counters (`FOLDS` / `CSE` / `LOADCSE` / `LICM` / `DCE` /
  `CONSTBRANCH` / `COPYPROP`) are **no longer emitted by the driver at all**, so
  the harness' `meta.get("DCE", 0)` is permanently `0`.

The ~44 guards in `scripts/test_opt_*.sh` were written against that lane. Their
**correctness** assertions still hold everywhere (`opt_exit == off_exit ==
expected` in every observed failure); only their *"the pass FIRED"* assertions
break. Example, `test_opt_dce.sh`:

```
[dead_arith] FAIL(under-fire)  opt_exit=13 off_exit=13 expected=13 DCE=0 exp_dce>=1
```

This is **a feature intentionally off**, not a broken optimization.

## Fix: probe the lane, skip loudly — do not hardcode a skip list

* `scripts/_opt1_lane_probe.py` — compiles one canary (saxpy-shaped multi-use
  global-array loop + dead local + foldable constant) through the dump driver
  **with `--opt` ON and OFF** and reports whether **any** legacy counter is
  strictly higher ON than OFF. Differential (not "> 0") so counters that also
  tick in plain -O0 cannot fake an active lane.
  * **Positive control**: the same canary is run through `--dump-regalloc`,
    which *does* call `ra_enable()`. It promotes 18 locals / 18 in register.
    So the allocator itself works — it is simply never armed on the `--opt`
    emission path. If the positive control ever fails the probe returns
    *unknown* and **nothing is skipped**.
  * Result is cached under `build/opt1_lane/` keyed by the dump driver's
    **content** inputs-hash, so any compiler/driver edit re-probes
    automatically. This is self-healing, not a static skip list.
* `scripts/lib_opt1_lane.sh` — `opt1_require_lane <name>` is sourced at the top
  of each affected guard. When the probe says `retired` it prints:

```
SKIPPED: --opt legacy opt1 optimizer lane is RETIRED (ba2e4bcf, 2026-07-21) — test_opt_dce asserts counters that can no longer fire
SKIPPED-REASON: feature intentionally OFF pending the SSA optimizer rewrite; NOT a broken optimization
SKIPPED-EVIDENCE: scripts/_opt1_lane_probe.py — no legacy counter is higher with --opt ON than OFF; --dump-regalloc positive control passes
SKIPPED-TRACKING: docs/ci_status_2026-07-25.md (see docs/adder_ssa_optimizer_design.md for the replacement pipeline)
[test_opt_dce] SKIP
```

and exits 0. When the probe says `active` the guard runs for real and a failure
is a **real bug**. When the probe is inconclusive the guard also runs for real.

## REAL BUGS found (not skipped away)

### 1. `ssa-evalorder` — the SSA `--opt` pipeline reorders side effects — **OPEN**

`scripts/test_opt_reglower.sh` case *D (eval-order/clobber soundness)*:

```
XFAIL(known-bug) eval-order: ref=214537 on=123628 off=214537
```

The program is `sc_o(1,40) - sc_o(2,7)`, etc., where `sc_o` appends its id to a
global (`g_seq = g_seq*10 + id`). The seed and the default `-O0` path evaluate
binop operands **RIGHT-then-LEFT** (`g_seq == 214365`). Under `--opt` (i.e. the
SSA pipeline) the operands evaluate **LEFT-then-RIGHT** (`g_seq == 123456`).
With side-effecting call operands the difference is directly observable, so
`--opt` output ≠ `--opt`-off output. **This is a genuine correctness divergence
in the SSA optimizer.**

Impact today: **none shipped** — nothing in the build is compiled with `--opt`
/ `ADDER_OPT2` (the default is byte-identical -O0, objdiff/kobjdiff clean).
It is a blocker for the Phase-4 `--opt` cutover.

Handling: recorded as an **XFAIL** in `test_opt_reglower.sh` (parts A–C of that
guard still run and PASS: value bit-exact, push/pop 102 → 52, caller-saved IR
scratch fires). The XFAIL is *not* a silent skip:

* every run prints `XFAIL(known-bug)` + `KNOWN-BUG: ssa-evalorder`;
* if the bug is ever fixed, the guard **fails** with `FAIL(xpass)` demanding the
  XFAIL branch and this doc entry be removed — so it can never rot into
  permanent blindness;
* if the **default** (`--opt` OFF) path ever gets it wrong, that is a hard FAIL
  with no XFAIL escape.

**Fix belongs in `adder/compiler/ssa_emit.ad`** (operand emission order for
binary operators must match the seed's right-before-left rule, or the seed +
`-O0` path must be changed in lockstep and the reference updated). Not done
here: this agent was scoped to `scripts/` + `docs/`.
