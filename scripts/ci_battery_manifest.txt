# scripts/ci_battery_manifest.txt — the bare-metal regression battery.
#
# One gate invocation per line, in shortest-first order. The CI job
# 'hamnix-bare-metal' round-robin-shards this list across a matrix of
# parallel runners (index % NSHARDS), so all gates keep running on every
# push but each shard finishes well under its timeout — 56 pure-TCG QEMU
# boots serially blew past the 40-min budget (~75 min needed) and the
# whole battery went permanently red, providing ZERO signal. Add a gate:
# drop a line here (order = fast→slow keeps shards balanced under round-
# robin). Wrapped gates (ci_run_gate.sh) emit the three-valued verdict
# (INCONCLUSIVE→warning on a TCG-starved runner); direct ones are hard
# PASS/FAIL. Blank lines and # comments are ignored.

# FIRST, and ~1 s: the stale-artifact canary. No QEMU. Fails when any tracked
# build artifact under build/ is older than a tracked build input (booting one
# makes every downstream verdict describe the WRONG build — the 2026-07-24
# office-suite false negative), or when a gate reuses a prebuilt artifact
# behind the banned `if [ ! -f "$IMG" ]` rebuild-only-when-absent shape.
bash scripts/test_artifact_freshness.sh
# SECOND, and ~1 s: the unregistered-gate canary. No QEMU. A gate script that
# no CI job runs is not coverage — it is a hole shaped like coverage, and it
# has already cost shipped bugs (tagquote/textContent, the DE ghost window,
# the broken installer, the ARM64 lane that silently stopped building). This
# fails when a NEW scripts/test_*.sh is neither registered here, nor run by a
# .github/workflows step, nor carrying an explicit "not in
# ci_battery_manifest.txt because <reason>" line in its header. The 879
# pre-existing dark gates are frozen in scripts/ci_ondemand_baseline.txt,
# which the same gate ratchets DOWN-only.
bash scripts/test_gate_registration.sh
# THIRD, and ~1 s: the FALSE-GREEN canary — the strictly worse sibling of the
# one above. An unregistered gate is a hole that looks like coverage; a
# false-green gate is wired up, actively green, and asserting nothing. On
# 2026-07-28 fourteen registered gates exited 0 while printing
# "ERROR: build_installer_img.sh failed" — proven by construction by stubbing
# that build script to exit 1. Root cause: ensure_installer_img returned the
# same non-zero for "skipped by request" and "the build FAILED", and its
# published idiom was `|| exit 0`. This gate bans that idiom outright, ratchets
# down the pre-existing sites (scripts/ci_softgreen_baseline.txt), and forbids
# a manifest line from discarding its gate's exit status with `|| true`.
bash scripts/test_gate_softgreen.sh
# FOURTH, and ~1 s: the CAPABILITY-VACUOUS canary, the third hole in the set.
# test_gate_registration.sh: nothing RUNS this gate. test_gate_softgreen.sh:
# this gate claims PASS for an assertion it could not observe. This one: this
# gate CANNOT observe its assertion on the machine CI runs it on, and nothing
# said so. Every runner in .github/workflows is `runs-on: ubuntu-latest`, which
# has no /dev/kvm; 20 gates registered right here open with
# `[ -e /dev/kvm ] || exit 0` and so have never asserted anything on GitHub —
# the DE visual/wallpaper/icon surface, the on-device hambrowse family, the
# installer NVMe end-to-end and webkit among them. Those gates are HONEST (a
# pure-TCG OVMF boot cannot finish in budget); the defect was that the hole was
# invisible. This gate PRINTS the count and the names on every run — including
# a ::warning:: annotation on a KVM-less runner, so a green build states what
# it did not cover — and ratchets the population down-only
# (scripts/ci_kvmdark_baseline.txt). Run the set for real on a KVM host with
# `bash scripts/ci_run_kvm_battery.sh`.
bash scripts/test_gate_kvmdark.sh

# test_arm64_a11_archive: A11 -- several compiled EL0 images in ONE embedded
# archive, loaded BY NAME, plus a real read(2) on the PL011. Each of those three
# claims is trivially fakeable and is asserted where it is not:
