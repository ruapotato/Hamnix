# scripts/wpt_reftest_baseline.txt -- SHRINK-ONLY record of the WPT
# REFTEST lane (tests/wpt/REFTEST_MANIFEST.txt): a test document
# compared PIXEL-EXACTLY against its <link rel="match"> reference,
# both rendered by our own engine.
#
# Regenerate with:  bash scripts/test_wpt_reftest_ratchet_host.sh --regen
# Regeneration REFUSES to loosen any marker below without
# --allow-loosen, so banking a fix cannot silently bank a regression.
#
# Rows (TAB-separated):
#   <test>\t<verdict>   did NOT pass at baseline
#   +<test>\tPASS      PASSED at baseline (the regression set)
#   ~<test>\tWEAK-PASS WEAK-PASSED at baseline
#
# VERDICTS
#   PASS       the relationship holds, and it is load-bearing on a
#              declaration the REFERENCE does not supply verbatim --
#              neutralize that declaration in the test alone and the pair
#              stops holding. The engine demonstrably applied something
#              this test is about.
#   WEAK-PASS  the relationship holds and CSS is load-bearing on it, but
#              only through declarations the reference repeats IDENTICALLY.
#              Both sides run the same code, so a shared bug cancels: real
#              work, tracked and ratcheted, but not conflated with a PASS.
#   FAIL       the relationship does not hold.
#   NONDISCRIMINATING
#              the relationship holds no matter WHICH of the test's
#              declarations is neutralized, and with all CSS removed. The
#              render does not depend on CSS at all, so an engine with no
#              CSS support would satisfy it too. Not evidence.
#   ERROR      a document, or a control, did not render.
#
# THE FIVE MARKERS. All are required: a baseline missing one is treated
# as unusable rather than defaulting to a value that guards nothing.
#
# #!PASS_FLOOR guards the ABSOLUTE pass count, not a ratio: the
# denominator grows when the engine improves (a NONDISCRIMINATING pair
# becomes discriminating) or when an exclusion is lifted, so a real fix
# can LOWER the ratio.
#
# #!WEAK_PASS_FLOOR -- the same guarantee for the weak class. It is a
# FLOOR and not a ceiling on purpose: a weak pass is a pair whose holding
# depends on CSS, so losing one is a capability loss, and the split exists
# to keep weak evidence OUT of the headline number, not out of the ratchet.
#
# #!ERROR_CEILING -- every vendored document must keep RENDERING. A
# change that makes the engine bail turns FAILs into ERRORs, which no
# pass floor can see. It is not zero: the round-2 import found a document
# that SIGSEGVs the engine (css/css-display/
# display-contents-dynamic-fieldset-legend-001.html -- needs its <script>;
# with the script removed it renders fine). That is an engine bug, not a
# runner limitation, so it may NOT be excluded, and banking it does not
# blind the gate: the check is also PER-TEST, so any OTHER document that
# starts erroring still reports INCONCLUSIVE.
#
# #!ND_CEILING -- the capability-loss detector. Under the previous
# (global-strip) model this ceiling ALSO capped progress, because fixing a
# test whose reference is a plain green square moved it FAIL ->
# NONDISCRIMINATING: 57 of 67 remaining failures could not have scored at
# all, and two genuine fixes landed in the bucket and read as nothing.
# Under the mutation model the class is MONOTONE in the right direction --
# a pair only enters it when the render stops depending on CSS -- so this
# ceiling now catches loss without capping gain.
#
# #!TREE_SHA256 -- over REFTEST_MANIFEST.txt and every document it
# names. Makes "never edit a vendored test or reference" enforced rather
# than merely stated, and stops rows being deleted from the manifest to
# launder a FAIL out of the lane. A real re-import changes it, which is
# the point: it forces a deliberate --regen that shows in the diff.
